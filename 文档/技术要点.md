# 技术要点（给接手者）

## 架构

```
原版客户端(Lua) ─ NetMsg → CNetMgr(C++) → TCP 127.0.0.1:9001 ─→ server/hakimi_server (Python, SQLite)
```

客户端保留原生通信路径，只在 `Logic/Login.Login` 最后时刻把地址设为 `127.0.0.1:9001`。`OFFLINE_STANDALONE=1` 时 `NetMsg:Send` 不再被拦截；但构建仍把 `LocalServer.lua`（约 100KB）作为登录夹具注入 NetMsg（提供 `ACCOUNT` 常量和 `autoLogin`），后续应精简为只保留这两项。

## 服务端代码

| 文件 | 职责 |
|---|---|
| `transport.py` | TCP 外层帧、粘包/分片、BPHash 校验 |
| `protocol.py` | 应用帧与动态类型编解码 |
| `storage.py` | SQLite：账号、角色名唯一、JSON 状态 |
| `login.py` | `LoginInfoVo` 组装 |
| `battle.py` | 按 `BattleInfoConfig` 生成逐波战报 |
| `gift.py` | 礼包列表/领取、进度奖励、活动列表 |
| `defaults.py` | 按 schema 生成可编码的空结构（**只用于补齐字段，不代表业务成功**） |
| `server.py` | 会话与命令路由（`(mod, cmd)` 分派） |

新增命令：在 `server.py` 路由中加 `(mod, cmd)` 分支（或拆到业务模块），状态存到 `record.state` 并 `repository.update_state`；响应结构查 `05_改造/schema/protocol_schema.json`，客户端如何消费查 `04_Lua源码/src/Logic__*.lua`；加完运行 `python 09_脚本/32_protocol_coverage.py` 更新覆盖清单。

## 协议关键结论（已验证，勿改）

- **BPHash**：每个字节按 signed char 符号扩展后参与异或；按无符号实现会让含中文/二进制的包校验失败。
- 强类型结构严格按 `protocol_codes.json` 字段顺序编码。
- `CostResult.contents` / `RewardResult.contents` 是动态 `object`，须带自描述类型。
- 动态对象里超出 int32 的数（如毫秒时间戳）必须编码为 **DOUBLE**；编成 INT64 时 Lua 会当成 ID 字符串，UI 做减法报错。
- ID 类 long 用 `defaults.long_id()` 编码。
- 登录信息必须 `asset=1000`，否则 `Logic/Login.OnLoginInfo` 静默停止。
- 实机启动顺序：`10:4 → 10:1(仅新号) → 10:2 → 10:7 → 16:7 → 10:9 → 47:2 → 13:12`。

## 客户端补丁关键结论

- Lua 字节码去符号，反编译源码有三类缺陷（`_UPVALUE` 占位、寄存器复用导致 self 错误、丢失局部变量）。**不能整体重编译反编译源码**。优先用 `bytecode_overrides.py`：先加载原字节码，再追加覆盖函数，保留原闭包。
- `18_build_offline.py` 的 2.10 节"跳过所有引导"日志已过时：`bytecode_overrides.py` 之后会覆盖 `Logic/Guide`，恢复原版 31 个引导模块（按剧情顺序，`Guide.setup()` 延迟 2500ms 首检）。
- `FightDrawGift` 引导补回了 `CN02BN04` 通关前置，否则会在 CN01BN02 后提前覆盖结算页。
- 主城早期 SIGSEGV（0xdead1007）的根因是同步响应在场景遍历中替换场景；现走真实 TCP 异步响应，已解决。
- 游戏读取内部存储 `files/assets/script.dat`；`install -r` 同版本不会重新解包，改 Lua 要用 `31_debug_deploy.py` 覆盖或 `pm clear`。
- 雷电 14 装 32 位包需 targetSdk 8→22（已做），首次启动需 `pm grant` 并点权限审查"继续"。
- 日志：`adb logcat -s TwLog:V`；补丁日志前缀 `[PATCH]`。
