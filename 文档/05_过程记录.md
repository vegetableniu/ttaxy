# 过程记录

## 稳定结论

### 基线和改造方法

用户提供的 1.0.8.0 APK 与项目原始样本 SHA-256 一致。去符号 Lua 反编译产物会丢 upvalue、局部变量和方法调用的 `self`，不能批量重编译作为产品代码。当前方法是执行原始字节码后只覆盖必要入口。

### 主城和登录

主城早期 `SIGSEGV` 的根因是本地同步响应在旧 Cocos2d-x 场景遍历中立即替换场景；延后 Main/Home 挂载后稳定。登录信息还要求 `asset=1000`，否则 `Logic/Login.OnLoginInfo` 会静默停止。

当前实机启动顺序：`10:4 CHECK_ACCOUNT → 10:1 CREATE（仅新账号）→ 10:2 LOGIN → 10:7 LOGIN_INFO → 16:7 DRAW_SP_REGISTER → 10:9 LOGIN_COMPLETE → 47:2 GET_SELEF_MENPAI → 13:12 CURRENT_SCORE`。客户端在 `Logic/Login.Login` 最后时刻设置 `127.0.0.1:9001`，解决干净安装没有区服偏好的问题。

### schema 和原生传输

schema 提取器原来只读取 `map(...)` 第一个参数，修复后得到完整类型和字段。原生 BPHash 必须把每个高位字节按 signed char 符号扩展后参与异或；按无符号字节实现会使带中文/二进制内容的包校验失败。该行为已有捕获帧和高字节回归测试。

`CostResult.contents`、`RewardResult.contents` 是动态 `object`，必须携带自描述类型。动态对象中的毫秒时间戳如果编码为 INT64，旧 Lua 客户端会当成 opaque ID 字符串；改用 DOUBLE 后 `refreshTime` 保持数值，结算 UI 可正常做减法。

### 账号和存档

账号、角色名和业务状态已迁入 SQLite。状态 JSON 当前包含体力、钱包、玩家等级/经验、通关关卡和每日次数。新账号创建、重复账号/角色名拒绝、非法创建不产生半条记录、进程重启恢复均有测试。

### 新手引导

发布包的 `Guide.getAllModules()` 被裁成空表。恢复时不能按数据库字母顺序排列，因为 `Guide.check()` 严格只检查队首；当前按剧情进度恢复 31 个模块。首次登录的本地 TCP 响应快于界面监听器安装，因此 `Guide.setup()` 在 2500ms 后执行第一次检查。干净账号已实机自动出现原版手型指引并完成第一关、第二关引导。

竞技领奖 `FightDrawGift` 模块原本只依赖一个临时 UI 标记；本地快速流程中该标记为 nil，导致它在 CN01BN02 后提前覆盖结算页。已按照原包 Guide 配置补回 `CN02BN04` 通关前置。尚缺第一关应发放的礼包和培养材料，因此升级、进化教学会被模块的 `isDone()` 跳过，这是下一项业务补齐重点。

### 战斗和结算

战报需要 typed value、Buff、被动、起手被动，以及每回合 starts/ends/cooldown 区段。服务端现按 `BattleInfoConfig.enemies` 为每波生成一个 TriggerVo，最后一波才置 finished。CN01BN01 单波和 CN01BN02 双波均已实机播放。

`EXIT(22:5)` 持久化通关、每日次数、体力、铜钱、经验和等级，并返回原结构 CostAndReward。实机完成两关后结果页每次显示 150 铜钱、10 经验，数据库累计铜钱 300、经验 20、两关通关，未再出现 `refreshTime` 类型错误。

普通关敌方精确阵容和奖励公式不在 APK 配置中；当前使用原包低级 NPC 模型和确定性公式驱动完整流程，证据等级仍为原型，不能标成与原服数值等价。
