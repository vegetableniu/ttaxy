# 项目结构

项目根目录为 `C:\Users\nkq\Desktop\nkq\game\hakimi`。桌面上的 `g` 和 `game` 是兼容旧脚本的目录联接；文档、脚本和新增代码统一使用相对路径。

| 路径 | 职责 | 修改规则 |
|---|---|---|
| `00_原始样本/` | 指定 1.0.8.0 APK 的只读工作副本 | 不手改 |
| `01_解包/` | APK、脚本包、数据库和资源包解包结果 | 由工具重建 |
| `02_分析/` | 模块索引、协议逆向、配置分析、战报说明 | 工具可改，导出物不手改 |
| `04_Lua源码/src/` | 去符号反编译源码，用于定位客户端消费方式 | 只读参考，不能直接作为产品脚本 |
| `05_改造/lua/` | 历史内嵌服务端原型，只作行为线索 | 不作为最终服务端 |
| `05_改造/patched/` | 构建生成的最小 Lua 覆盖模块 | 不手改 |
| `05_改造/schema/` | 从原包提取的类型、字段顺序、枚举和命令表 | 由提取器生成 |
| `05_改造/apktool/` | Android 清单、DEX 和资源打包工作区 | 由补丁脚本修改 |
| `06_构建/` | APK、脚本包、SQLite 测试库、日志和验收截图 | 构建/测试产物 |
| `09_脚本/` | schema 提取、Lua 生成、APK 构建、部署和覆盖审计 | 手工维护 |
| `server/hakimi_server/` | 最终本机 TCP 服务端 | 手工维护 |
| `server/tests/` | 协议、存档、启动序列和战斗回归测试 | 手工维护 |
| `文档/` | 结构、构建、测试、过程和协议覆盖 | 每轮同步更新 |

## 客户端最小改造

- `09_脚本/bytecode_overrides.py`：先加载原始 Lua 字节码，再覆盖必须离线化的入口。目前负责本机地址、离线账号入口、引导顺序与时序、战斗回放和已证实缺陷修正。
- `09_脚本/17_gen_localserver.py`：合成 schema、历史原型和字节码覆盖。
- `09_脚本/18_build_offline.py`：编译 Lua、回填 `script.dat`、替换 Android 内容并签名。
- `09_脚本/25_patch_smali.py`：Android 兼容和启动阶段补丁。
- `09_脚本/31_debug_deploy.py`：保留应用数据的快速脚本替换与日志采集。
- `09_脚本/32_protocol_coverage.py`：生成逐命令覆盖清单，默认零值应答不计为完成。

## 独立服务端

- `transport.py`：TCP 外层帧、流分片缓存和与原生 C++ 一致的有符号字节 BPHash。
- `protocol.py`：Lua 应用帧、自描述对象、强类型对象和动态 `object` 编解码。动态大整数使用 DOUBLE，避免 Lua 将 INT64 当作 ID 字符串。
- `storage.py`：SQLite 账号、角色名唯一约束和 JSON 状态持久化。
- `login.py`：登录快照、角色、货币、体力、阵容和通关进度恢复。
- `battle.py`：按 `BattleInfoConfig` 生成逐波战报、阵容、确定性敌方单位和关卡结算。
- `server.py`：连接、会话校验、显式命令路由、待结算战斗和存档。
- `defaults.py`：只补齐可编码结构，不能代表业务成功。

客户端已恢复原生 `NetMsg → CNetMgr → TCP` 通路，地址固定为 Android 本机 `127.0.0.1:9001`。调试时用 `adb reverse` 转发到电脑上的 Python 服务端。未知命令明确失败并断开，避免空对象伪装成功后污染存档。
